# 山竹视频复刻制作驾驶舱 UI 设计

## 1. 目标

把现有以命令和 Markdown 文件为主的视频复刻流程，升级为 Obsidian 内的可视化“制作驾驶舱”。面向不熟悉 JSON、命令和目录结构的用户，让用户能够：

1. 看懂当前项目进行到哪一步、正在做什么、是否出错。
2. 在付费生成前直接编辑人物、产品、场景和分镜内容。
3. 确认后锁定本次生成版本，避免生成过程中误改字段或顺序。
4. 在同一页面查看参考资产、首尾帧、视频片段和最终成片。

本次采用已经选定的 **A｜制作驾驶舱**，不引入 React、Tailwind 或新的第三方依赖，直接使用 Obsidian 原生 `ItemView`、DOM API 和 CSS 变量，降低安装与升级风险。

## 2. 用户流程

### 2.1 进入驾驶舱

- 点击左侧“山竹视频复刻”图标，默认打开制作驾驶舱，不再直接弹出新建项目窗口。
- 驾驶舱顶部提供“新建复刻项目”按钮，继续复用现有本地视频选择和拆解流程。
- 自动选中最近更新的项目；顶部下拉框可切换其他项目。

### 2.2 编辑与确认

- AI 分析完成后，项目进入“等待确认”状态。
- 用户可编辑人物提示词、产品提示词、场景提示词和每个分镜的字段。
- 分镜支持“上移、下移”，不实现复杂拖拽排序。
- 保存时先校验必填字段、场景引用和产品引用，再原子写入 `generation-request.json`。
- 点击“确认并开始生成”后，界面进入锁定状态；本次运行期间不再允许编辑和排序。

### 2.3 生成与查看

- 生成过程中每 2 秒读取结构化状态，不解析终端文本或日志。
- 当前任务、阶段进度、已完成镜头数和错误信息实时更新。
- 已生成的图片、视频和最终成片可直接预览或在 Obsidian 中打开原文件。
- 模型不可用时显示明确错误，并提供“更换模型”入口。

## 3. 页面结构

### 3.1 顶部工具栏

- 品牌：山竹 · 视频复刻。
- 项目选择器：显示项目名称和更新时间。
- 状态：准备中、等待确认、正在生成、部分失败、已完成。
- 主操作：新建项目、刷新、更换模型。

### 3.2 左侧导航

采用成熟的单视图分页模式：

1. **总览**：总进度、当前任务、流程阶段、镜头状态。
2. **资产**：人物、产品、场景参考图。
3. **分镜**：脚本编辑、排序、首尾帧和视频状态。
4. **成片**：视频片段和最终拼接结果。
5. **设置**：分析模型、图片模型、视频模型及使用说明。

窄窗口下导航变为顶部横向标签，不产生横向滚动。

### 3.3 总览页

- 项目标题、状态说明和总进度条。
- 五阶段流程：本地拆解 → AI 分析 → 参考资产 → 分镜视频 → 拼接成片。
- 当前任务区：当前步骤、所用模型、开始时间和等待时长。
- 镜头状态矩阵：最多 12 个镜头，显示等待、生成中、完成或失败。
- 失败镜头在原位置显示错误原因，不使用只显示“失败”的泛化提示。

### 3.4 资产页

- 人物参考板独立分区。
- 产品参考板独立分区，不与环境混合。
- 场景参考图只显示纯环境资产。
- 每项显示名称、生成状态、是否复用和预览图。
- 点击预览图打开对应 Obsidian 文件；MVP 不提供图片裁剪和涂改。

### 3.5 分镜页

每个分镜使用可折叠编辑区，包含：

- 标题、时长、场景、产品引用。
- 剧情、台词、环境、镜头语言。
- 首帧提示词、尾帧提示词、视频提示词。
- 上移、下移、保存。
- 已确认项目只读展示，并显示“本次生成版本已锁定”。

保存时保持固定 JSON 结构；用户不会直接编辑 JSON。字段缺失、场景不存在或产品不存在时，在对应字段下方显示错误，不写入不完整数据。

### 3.6 成片页

- 按镜头顺序展示首帧、尾帧和视频片段。
- 失败镜头保留占位和错误信息，不打乱后续镜头顺序。
- 全部片段完成后显示最终成片。
- 提供“打开文件”按钮，不复制、不移动、不删除原文件。

## 4. 状态与进度来源

### 4.1 数据优先级

1. `.work/generation-state.json`：当前运行状态和当前步骤，作为实时状态权威来源。
2. `project.json`：资产路径、镜头产物、错误和最终成片。
3. `generation-request.json`：用户可编辑草案和模型设置。

界面不读取终端输出，不依赖其他插件的可视化页面，也不解析自然语言日志。

### 4.2 进度计算

进度是阶段进度，不伪装成算力平台的精确百分比：

- 本地拆解完成：15%。
- AI 分析完成：30%。
- 参考资产完成：45%。
- 分镜视频：45%～90%，按完成镜头数线性计算。
- 正在拼接：95%。
- 最终成片完成：100%。

当前任务仍在平台处理中但没有精确进度时，使用活动状态条和已等待时间，不显示虚假数字。

## 5. 组件边界

采用高内聚、低耦合的四层结构：

1. **`replica-workbench.cjs`**：Obsidian `ItemView`、标签切换、事件绑定和渲染。
2. **`replica-ui-state.cjs`**：把三个 JSON 文件转换为稳定的页面 ViewModel，并计算阶段进度。
3. **`replica-editor.cjs`**：纯函数处理字段更新、分镜排序、校验和锁定判断。
4. **`main.js`**：注册视图、复用现有生成流程、提供读取与原子保存接口。

UI 文件不直接调用图片或视频接口；生成模块也不依赖 UI。未来替换图片模型、视频模型或增加新资产类型时，只调整数据映射和生成模块。

## 6. 实时更新与生命周期

- 视图打开时开始每 2 秒刷新；视图关闭时立即停止，避免后台重复定时器。
- 同时监听项目 JSON 文件的 Obsidian `modify` 事件，实现快速更新。
- 渲染前比较轻量状态摘要，数据未变化时不重建整个页面。
- 图片使用文件资源 URL；缺失图片显示明确占位，不抛出未处理异常。
- 插件卸载时注销视图、定时器和事件监听。

## 7. 错误与空状态

- 没有项目：显示新建项目入口和三步说明。
- 正在分析或生成：显示骨架占位、活动状态条和当前步骤。
- 请求字段错误：定位到具体分镜和字段。
- 模型 404/下架：显示模型名称、返回状态和“更换模型”按钮。
- 图片或视频文件缺失：显示文件路径和“重新检查”按钮，不自动重新付费生成。
- 读取到旧版项目：尽可能展示；缺失 `products` 时按空数组处理。

## 8. 视觉规范

- 使用 Obsidian 当前主题变量，兼容明暗主题。
- 中性深灰导航配单一绿色状态色；不用紫色霓虹、外发光和大面积渐变。
- 数据数字使用等宽字体，正文跟随 Obsidian 字体。
- 容器用细边框和留白分组，减少无意义卡片嵌套。
- 所有按钮提供悬停、按下、禁用和键盘焦点状态。
- 尊重 `prefers-reduced-motion`，动画只使用 `transform` 和 `opacity`。

## 9. 测试与验收

### 9.1 自动测试

- ViewModel：各项目状态映射、阶段进度、当前步骤和错误信息。
- 编辑器：字段更新、分镜上下移动、引用校验、确认后拒绝修改。
- 插件加载：注册视图、命令和图标；卸载时释放资源。
- 向后兼容：版本 1、2、3 项目都能打开，不影响现有生成测试。

### 9.2 手动验收

在不触发新付费任务的测试项目上确认：

1. 驾驶舱能打开并切换项目。
2. 总览能显示真实生成进度和失败原因。
3. 未确认项目可以编辑和排序，确认后变为只读。
4. 人物、产品、场景、首尾帧和视频能正确预览。
5. 明暗主题和窄面板均可用。

## 10. 本次不做

- 不做时间轴剪辑器、字幕编辑器或视频裁剪。
- 不做复杂拖拽、多人协作或云端项目同步。
- 不读取终端日志推算进度。
- 不替换现有生成流程，不新增新的算力接口。
- 不在当前长任务运行期间重启 Obsidian；代码验收通过后再同步并安全启用。
