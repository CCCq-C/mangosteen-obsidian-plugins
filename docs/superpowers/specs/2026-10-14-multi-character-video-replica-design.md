# 山竹视频复刻：动态多角色设计

## 目标

视频分析不再假定只有一个主角。系统从截图和转写中识别实际参与剧情的角色，为每个需要保持一致性的角色建立独立人物参考板，并由每个分镜声明本镜头出现的角色。

## 数据契约

- 草案版本升级为 `version: 6`，项目存储仍沿用稳定的 `schemaVersion: 6` 布局。
- `characters[]` 是人物唯一主数据；每项包含 `id`、`role`、`prompt`、`voiceProfile`。
- `shots[].characterIds[]` 只引用本镜头实际出现且需要固定形象的角色。
- 为兼容旧项目，读取旧 `character` 时自动迁移为单项 `characters[]`，旧分镜自动绑定该角色；写入时保留 `character = characters[0]` 兼容镜像。
- 项目产物使用 `characterAssets[]`；`characterAsset` 保留为首角色兼容镜像。

## 角色判定

- 独立角色：多次出现、说台词、推动剧情或需要跨镜头保持外观的人物。
- 背景人物：偶发路人、人群或不参与剧情者默认不创建人物参考板。
- 分析必须给每个独立角色稳定 ID，并在每个镜头填写 `characterIds`。

## 用户流程

1. AI 分析后在“资产”页展示角色清单。
2. 用户可编辑角色名称、人物提示词和声音设定。
3. 用户点击“确认角色列表”后才能提交付费生成；修改任一角色会自动取消确认。
4. 分镜编辑页可勾选本镜头出现的角色。

## 生成行为

- 只为当前项目缺失或提示词已变化的角色生成参考板。
- 每个镜头只携带 `characterIds` 对应的人物参考图，不把其他角色误传入。
- 首帧生成和支持多图参考的视频模型按顺序传入：人物参考板（可多张）→ 场景板 → 产品板。
- 生成指纹包含本镜头全部人物的 ID、提示词、声音设定和参考图哈希，角色变化会使该镜头失效，但不影响无关镜头。

## 兼容与安全

- 旧单人物项目可直接打开、编辑和继续生成，不要求重跑分析。
- 已确认或正在生成的镜头仍按不可变快照执行。
- 角色、场景、产品和镜头 ID 都继续执行现有安全校验。
- 本次升级不自动改写已完成的历史付费验收项目，也不重新提交任何付费任务。
