# 固定人物视频生成设计

日期：2026-10-10
状态：待用户书面规格确认

## 1. 目标

用户选择已固定的人物参考资产，输入提示词或脚本后，系统自动生成保持人物五官、发型、服装和场景特征一致的视频镜头。MVP 只开放 MiniMax-H3 与 Seedance 系列，严格根据当前接口接受的字段发送请求。

## 2. 范围

### 包含

- 可复用的人物参考资产与场景参考资产。
- 多参考图生成镜头关键帧。
- MiniMax-H3 首帧/可选尾帧生成视频。
- Seedance 参考图片生成视频。
- 两个相邻镜头的一致性验证。

### 不包含

- 原视频截图作为生成参考。
- 上一镜头尾帧默认接龙。
- Kling、Wan 或其他视频模型。
- 自动成片剪辑、配音、字幕和批量全片生成。

## 3. 接口事实

资料来源：

- 生视频接口：https://86bdknokqu.apifox.cn/9260936m0.md
- 首尾帧接口：https://86bdknokqu.apifox.cn/514901345e0.md
- 多图图生图接口：https://86bdknokqu.apifox.cn/495788522e0.md

约束：

1. MiniMax-H3 支持 `first_image` 与 `last_image`；存在首尾帧时不发送 `ratio`。
2. Seedance 2.0 最多 9 张参考图；Seedance 2.5 最多 30 张参考图。
3. 首尾帧与 `referenceImages`、`referenceVideos`、`referenceAudios` 互斥。
4. 图生图通过 multipart 重复传入 `image` 字段接收多张图片。
5. 所有视频参考素材最终必须是公网 HTTPS URL；本地图片先经山竹账号中心临时上传。

## 4. 模型选择规则

视频复刻功能只显示当前账号已经开通、且满足以下规则的模型：

- MiniMax-H3：模型 ID 忽略大小写后等于 `minimax-h3`。
- Seedance：模型 ID 包含 `seedance`，或属于现有兼容 ID `sd-2.0-fast`、`sd-2.0-mini`、`sd-2.0-stable`。

不根据名称猜测其他模型能力。账号未返回上述模型时，生成前直接提示用户刷新山竹账号中心或开通对应分组。

## 5. 参考资产

### 人物资产

每个人物拥有稳定 ID，并保存：

- 人物三视图。
- 五官近景。
- 不可变化特征：发型、脸型、五官、年龄感、体型、服装、配饰、颜色。
- 负面约束：禁止改变的身份和外观特征。

### 场景资产

每个场景拥有稳定 ID，并保存：

- 场景宽幅参考图。
- 固定物体及相对位置。
- 室内/室外、海边/陆地、时间、天气、光线与主色调。
- 禁止出现或禁止变化的环境特征。

参考资产保存于 Obsidian：

```text
山竹视频资产库/
├── 人物/<character-id>/
│   ├── 人物三视图.png
│   ├── 五官近景.png
│   └── character.json
└── 场景/<scene-id>/
    ├── 场景参考图.png
    └── scene.json
```

## 6. 数据流

### 6.1 脚本规划

输入提示词或脚本后，生成结构化镜头：人物 ID、场景 ID、构图、人物动作、表情、镜头运动、时长、首帧描述和可选尾帧描述。

### 6.2 生成镜头关键帧

图生图接口同时输入人物三视图、五官近景和场景参考图。默认最多 3 张资产图；若需要连续动作，可额外加入上一镜头尾帧，但仅用于生成下一镜头关键帧。

每个镜头至少生成一张首帧。只有必须精确控制结束姿势或构图时才生成尾帧。

### 6.3 MiniMax-H3 适配

请求只发送：

```json
{
  "model": "MiniMax-H3",
  "prompt": "动作、表情和运镜描述",
  "duration": 4,
  "resolution": "768p",
  "first_image": "https://临时图片地址",
  "last_image": "https://可选尾帧地址"
}
```

不发送 `ratio`、`referenceImages`、`referenceVideos` 或 `referenceAudios`。

### 6.4 Seedance 适配

请求只发送：

```json
{
  "model": "seedance-2.5",
  "prompt": "动作、表情和运镜描述",
  "duration": 4,
  "resolution": "720p",
  "ratio": "9:16",
  "referenceImages": [
    "https://镜头首帧临时地址",
    "https://可选镜头尾帧临时地址"
  ]
}
```

不发送 `first_image` 或 `last_image`。视频阶段只使用已经锁定人物和场景的关键帧，不再次加入人物三视图、场景参考图或原视频截图。

## 7. 代码边界

### 山竹生图

新增向后兼容的多图方法，例如 `generateEditMulti(prompt, images)`。现有 `generateEdit(prompt, image)` 保持不变并转调多图方法。multipart 请求为每张图片重复写入 `image[]` 部分。

### 山竹视频

- 增加本地 `referenceImageFiles` 临时上传能力。
- 增加模型族识别与字段互斥校验。
- MiniMax-H3 自动删除 `ratio` 并拒绝参考素材混用。
- Seedance 参考图模式拒绝首尾帧字段。

### 山竹视频复刻

- 引入人物 ID、场景 ID 和关键帧路径。
- 只允许选择当前账号可用的 MiniMax-H3 与 Seedance。
- 先生成全部关键帧，再逐镜提交视频任务。
- 单镜头失败不影响已完成资产和其他镜头。

## 8. 错误处理

- 不支持的模型：生成前终止，不产生费用。
- 参考字段冲突：本地校验终止，不请求平台。
- 临时上传失败：保留本地关键帧并允许重试。
- 某镜头生成失败：记录模型、步骤和中文错误，允许单镜头重试。
- 接口返回未知能力：不自动降级到其他模型，由用户选择可用模型。

## 9. MVP 验收

使用同一人物和同一场景生成两个相邻镜头：

1. 多图图生图请求成功，关键帧保留人物和场景特征。
2. MiniMax-H3 请求仅包含首帧或首尾帧字段，不包含参考素材和比例。
3. Seedance 请求仅包含参考图片，不包含首尾帧字段。
4. 两个镜头人物五官、发型、服装和场景固定物保持一致。
5. 图片、视频、请求状态和错误信息均可在 Obsidian 项目目录查看。

## 10. 测试顺序

先运行不计费的单元测试和模拟集成测试，再使用当前山竹账号执行最小真实测试：一套人物资产、一套场景资产、两个关键帧；分别选择 MiniMax-H3 与一个账号实际可用的 Seedance 模型各生成一段 4 秒视频。
