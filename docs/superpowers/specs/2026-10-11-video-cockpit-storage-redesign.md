# 山竹视频制作驾驶舱与媒体存储根治设计

## 1. 目标

在不改变现有算力接口和付费安全规则的前提下，解决两类问题：

1. 将视频复刻界面升级为三栏制作驾驶舱：左侧镜头队列、中间分镜编辑、右侧生成监控。
2. 从山竹生图、山竹视频和山竹视频复刻三方的保存接口入手，消除“一次任务一个单文件文件夹”、二次复制、旧状态冲突和标题改动产生残留文件的问题。

本设计使用现有 Obsidian `ItemView`、原生 DOM、CSS Container Queries 和 CommonJS，不引入 React、Tailwind、状态管理框架或新的运行时依赖。

## 2. 当前问题与根因

### 2.1 媒体文件

- 山竹生图的 `persistGeneration()` 为每次调用创建时间戳目录，再写入 `图片-1.png`。当前真实库中 64 个任务目录均只有一个文件。
- 山竹视频的 `saveCompletedVideo()` 为每个任务创建 `山竹视频/<taskId>/`，再写入一个以长提示词命名的视频。当前真实库中 24 个任务目录均只有一个文件。
- 山竹视频复刻等待上述插件保存完成后，再把视频复制到项目的 `03-视频片段/`，形成全局记录与项目文件两份副本。
- 视频复刻使用“镜头编号 + 可编辑标题”组成文件名。用户修改标题或重新生成后，旧文件路径不会被替换，导致同一编号出现多个首帧、尾帧和视频。

### 2.2 项目状态

- 旧的 `.work/generation-state.json` 与新的 `.work/generation-queue.json` 同时表达运行状态。
- 当前真实项目中，`project.json` 与队列显示镜头 008 正在生成，旧状态文件仍显示“已停止”。
- UI 需要自行判断多个文件谁更新、谁可信，容易显示错误状态。

根因不是用户整理不当，而是三个插件没有统一的“输出目标”协议，并且新旧生成流程各自维护状态。

## 3. 设计原则

1. **直接写入最终位置**：项目调用媒体插件时，不再先写全局历史目录再复制。
2. **稳定路径只使用 ID**：镜头标题只做展示，不参与文件路径。
3. **一个活动状态源**：当前运行只读取 `active-run.json`；历史运行使用不可变快照。
4. **默认不破坏历史文件**：旧项目继续可读，迁移必须在任务结束后由用户确认触发。
5. **付费请求不可重复**：沿用生成计划哈希、队列占位、任务 ID 恢复与停止后不再提交新任务的安全规则。

## 4. 统一媒体保存协议

### 4.1 输出目标

山竹生图和山竹视频对内部调用增加可选 `outputTarget`：

```js
{
  owner: "video-replica",
  projectId: "project_xxx",
  shotId: "008",
  assetType: "first-frame" | "last-frame" | "shot-video" | "reference",
  destinationPath: "山竹视频复刻/<项目>/03-分镜/008/视频.mp4",
  overwrite: "replace-current"
}
```

规则：

- `destinationPath` 存在时，媒体插件直接保存到该位置，并把该路径写回任务记录。
- 异步任务提交成功后，完整 `outputTarget` 必须随任务 ID 持久化；Obsidian 重启后仍能把完成结果保存到原项目位置。
- 不再创建全局任务文件夹，也不再由视频复刻执行二次复制。
- `destinationPath` 必须经过 Vault 根目录约束、路径规范化和扩展名白名单校验。
- 相同任务 ID 重试保存时覆盖同一目标；不得创建带 `(1)` 或标题后缀的新文件。
- `outputTarget` 缺失时视为用户独立使用媒体插件，走按月份归档的默认路径。

### 4.2 独立生图与视频任务

```text
山竹创作记录/
├── 图片/2026-10/
│   └── 20261011-150051-task_abcd-01.png
└── 视频/2026-10/
    └── 20261011-151302-task_efgh.mp4
```

- 不使用完整提示词作为文件名。
- 同一次多图任务写入同一月份目录，以任务 ID 和序号区分。
- 任务历史继续保留提示词、模型、费用、任务 ID 和文件路径，不依赖目录名称表达信息。

## 5. 项目目录

新项目使用 `layoutVersion: 6`：

```text
山竹视频复刻/<项目ID-短标题>/
├── 00-项目总览.md
├── 01-原始素材/
│   ├── 原视频.mp4
│   ├── 台词转写.md
│   └── 抽帧/
├── 02-参考资产/
│   └── 参考资产.md
├── 03-分镜/
│   ├── 001/
│   │   ├── 首帧.png
│   │   ├── 尾帧.png
│   │   └── 视频.mp4
│   └── 002/
├── 04-最终成片/
│   └── 最终成片.mp4
└── .mangosteen/
    ├── project.json
    ├── draft.json
    ├── active-run.json
    ├── runs/
    │   └── <run-id>.json
    └── history/
```

约束：

- `001` 等稳定镜头 ID 是目录主键；修改标题、台词和顺序不改变已有文件路径。
- 当前版本固定使用 `首帧.png`、`尾帧.png` 和 `视频.mp4`，避免同一镜头不断堆积不同标题文件。
- 重新生成前，把被替换文件移动到 `.mangosteen/history/<时间>/<镜头ID>/`；驾驶舱默认不展示历史版本。
- 人物、场景和产品的可复用原图仍由 `山竹视频资产库` 保存。项目中的 `参考资产.md` 使用 Obsidian 嵌入展示，并在运行快照中记录路径与 SHA-256，不复制资产。
- 导出项目时再执行“打包项目”，将引用资产复制到导出包；本次不开发导出功能。

## 6. 项目数据结构

### 6.1 `project.json`

稳定项目资料和最终结果：

```json
{
  "schemaVersion": 6,
  "projectId": "project_xxx",
  "title": "送福利任务复刻",
  "source": {},
  "shots": [{ "id": "001", "currentArtifacts": {} }],
  "finalVideoPath": "",
  "updatedAt": ""
}
```

不保存“当前正在生成”之类的易变状态。

### 6.2 `draft.json`

用户可编辑的视觉风格、人物、场景、产品、模型设置和结构化分镜。未加入队列的镜头可继续编辑；生成中的镜头由运行快照锁定。

### 6.3 `active-run.json`

唯一活动运行状态源：

```json
{
  "runId": "run_xxx",
  "status": "processing",
  "queue": ["008", "009", "010"],
  "activeShotId": "008",
  "shots": {
    "008": {
      "status": "video-processing",
      "stage": "provider-generation",
      "progress": 68,
      "taskId": "task_xxx",
      "elapsedMs": 402000,
      "error": null
    }
  },
  "updatedAt": ""
}
```

- 数字进度仅在算力平台提供时展示；否则展示阶段和等待时间。
- 当前队列、任务 ID、停止请求和镜头锁均在这里表达，不再读取旧 `generation-state.json` 判断当前状态。

### 6.4 `runs/<run-id>.json`

确认后的提示词、模型、参考图路径、内容哈希、任务 ID、结果和费用记录组成不可变运行快照。运行结束后，`active-run.json` 原子归档为对应快照，再清空活动指针。

## 7. 三栏制作驾驶舱

### 7.1 左侧：镜头队列

- 固定显示镜头编号、标题、当前状态和状态点。
- 状态限定为：草案、已排队、生成中、已完成、失败、已停止。
- 点击镜头切换中间编辑器和右侧监控。
- 生成中的镜头锁定；其他镜头仍可编辑、选择和加入当前队列。

### 7.2 中间：分镜编辑器

- 顶部显示镜头 ID、时长、模型、比例和锁定原因。
- 参考资产分为人物、场景、产品三类，显示实际绑定结果。
- 分镜内容按剧情段落编辑，每段包含起止时间、画面动作、台词、情绪与声音、景别与运镜、环境。
- 完整视频提示词作为可展开预览，不把所有长文本默认铺满页面。
- 保存只更新 `draft.json`；不会直接触发付费请求。

### 7.3 右侧：生成监控

- 显示当前镜头的参考资产检查、首帧准备、任务提交、平台生成、保存到项目五个阶段。
- 显示模型、任务 ID、已等待时间和算力平台提供的真实进度。
- 错误显示具体镜头、发生阶段、是否已提交付费任务和下一步动作。
- 不解析终端日志，不根据等待时间伪造百分比。

### 7.4 响应式规则

- 宽屏：三栏同时显示。
- 中等宽度：右侧监控移动到编辑器下方。
- 窄窗口：镜头列表变为顶部下拉选择，编辑器和监控单列排列。
- 使用容器查询适应 Obsidian 左右分栏、底部面板和独立窗口。

## 8. 状态与错误处理

错误使用固定结构：

```json
{
  "code": "MODEL_CATALOG_EMPTY",
  "source": "video-plugin",
  "stage": "preflight",
  "message": "视频模型列表暂未同步",
  "action": "重新读取模型",
  "retryable": true,
  "paidTaskSubmitted": false,
  "at": ""
}
```

错误分为：输入校验、模型配置、平台请求、任务查询、下载保存、文件持久化和旧状态迁移。失败镜头不会阻塞其他已提交任务，也不会自动重复提交不确定的付费请求。

## 9. 安全迁移

### 9.1 新项目

直接使用版本 6 目录和统一输出协议。

### 9.2 历史项目

- 旧结构保持只读兼容，不自动迁移。
- 项目存在 `queued`、`processing`、`saving` 或未核对的付费任务时，“整理当前项目”按钮禁用。
- 用户确认后创建迁移清单；先复制到新位置并核对文件大小和 SHA-256，全部验证通过后才移动旧文件。
- 所有新 JSON 先写临时文件，再原子替换。
- 验证成功后把旧文件移入 `.mangosteen/history/migration-<时间>/`，不直接删除。
- 迁移失败时恢复原路径和原 JSON，项目仍可使用旧结构打开。

### 9.3 全局历史目录

- 不自动删除现有 `生图记录/` 与 `山竹视频/`。
- 独立提供“整理历史记录”操作：把单文件任务目录归并到月份目录，更新任务路径并校验哈希。
- 视频复刻项目中的重复副本只有在确认目标文件存在且哈希一致后，才能列为可清理项；真正删除仍需用户二次确认。

## 10. 组件边界

1. **媒体输出适配器**：山竹生图和山竹视频负责安全写入 `outputTarget`，不理解视频复刻业务。
2. **项目存储层**：视频复刻负责计算项目路径、原子写 JSON、版本归档和迁移。
3. **运行状态层**：队列负责更新 `active-run.json`，UI 不直接修改运行状态。
4. **驾驶舱 UI**：只读取稳定 ViewModel，调用保存草案、提交选择、停止队列和迁移命令。

每层通过明确对象传参，不读取对方内部目录约定或设置文件。

## 11. 验收标准

1. 连续生成 10 张单图后，只产生月份目录中的 10 个文件，不产生 10 个单文件子目录。
2. 视频复刻生成一个镜头时，最终视频只写入项目 `03-分镜/<ID>/视频.mp4`，不在 `山竹视频/<taskId>/` 产生第二份。
3. 修改镜头标题并重新生成，不产生新的标题路径；旧版本进入隐藏历史目录。
4. 同一时间 UI 只从 `active-run.json` 得到一个当前状态，不再出现“项目生成中、旧状态已停止”的冲突。
5. 三栏驾驶舱在约 1200px、720px、360px 容器宽度下均可操作，不遮挡按钮或错误信息。
6. 旧项目在不迁移时仍可打开、查看和继续生成；迁移中断后原项目可恢复。
7. 当前已经提交的平台任务不会因插件升级、文件整理或 UI 刷新被重复提交。

## 12. 本次不做

- 不修改算力平台接口和模型选择规则。
- 不加入并发生成；继续使用当前队列执行方式。
- 不做复杂时间轴、视频剪辑或字幕编辑器。
- 不自动删除历史文件。
- 不在当前镜头 008 仍生成时部署或重载插件。
